## 5. สถานะคำขอ [D] A2 (5 สถานะของโจทย์) + ⚠️A-11 (สถานะที่เพิ่ม)

## 8. SLA และการแจ้งเตือน [D] US-O02
**วันเริ่มนับ (D0):** วันที่ชำระสำเร็จ ถ้าเป็นวันทำการและก่อน 16:30 · ถ้าไม่ใช่ → วันทำการถัดไป
**กำหนดเสร็จ:** วันทำการที่ N หลัง D0 (N = SLA ของบริการ) เวลา 16:30
**หยุดนับ:** ระหว่าง `NEED_FIX` เมื่อประชาชนส่งแก้ไข กำหนดเสร็จใหม่ = กำหนดเดิม + จำนวนวันทำการในช่วง (วันที่ตีกลับ, วันที่ส่งแก้ไข] (ไม่นับวันตีกลับ นับวันส่งแก้)
**หยุดเมื่อปิดงาน:** `COMPLETED` หรือ `REJECTED` (เวลาปิด = closed_at) · ทันกำหนด ⇔ closed_at ≤ กำหนดเสร็จ

- `ปกติ` วันคงเหลือ ≥ 2 · `ใกล้ครบกำหนด` (เหลือง) วันคงเหลือ ≤ 1 และ ตอนนี้ ≤ กำหนดเสร็จ · `เกินกำหนด` (แดง) ตอนนี้ > กำหนดเสร็จ ⚠️A-17
- ตัวอย่าง กำหนด ศ. 4 ธ.ค. 16:30: อ.1 = ปกติ (เหลือ 3) · พ.2 = ปกติ (2) · พฤ.3 = ใกล้ (1) · ศ.4 16:30 = ใกล้ (0) · ศ.4 16:31 = เกินกำหนด

## 15. Test hook (เฉพาะ `TEST_MODE=1`) และ BUG_MODE
- `POST /api/test/reset` → ล้างและ seed ใหม่ + นาฬิกากลับเป็นค่าเริ่มต้น
- `PUT /api/test/clock {"now":"<ISO+07:00>"}` · `GET /api/test/clock`
- `POST /api/test/payments/<ref>/pay {"amount":<int>}` = ธนาคารจำลองยิง callback
- `POST /api/test/documents/<docNo>/tamper` = แก้ข้อมูลเอกสารที่เก็บไว้ (เพื่อทดสอบลายเซ็นไม่ตรง)
- `BUG_MODE=B03,B07` (คั่นด้วยจุลภาค) เปิดบั๊กตาม `BUGS.md` ทีละหลายตัวได้ · ไม่ตั้ง = เว็บถูกต้อง
