## 3. วิธีพิสูจน์ว่า test จับบั๊กได้

| ขั้น | ทำอะไร | ต้องเห็นอะไร |
|---|---|---|
| 1 | รัน **ชุดเต็ม 51 TC** กับเว็บถูกต้อง: `TEST_MODE=1` (ไม่ตั้ง `BUG_MODE`) | ผ่านครบ 51/51 · ถ้าไม่ครบให้แก้เว็บ (หรือแก้ test ถ้าผิดที่ test) ก่อนไปขั้นต่อไป |
| 2 | รันซ้ำอีกรอบทันที (ไม่ restart เว็บ) | ผ่านครบ 51/51 อีกครั้ง (พิสูจน์ว่า reset ทำให้ผลซ้ำได้ ไม่ใช่ผ่านเพราะข้อมูลเหลือจากรอบก่อน) |
| 3 | สำหรับ B01 ถึง B12 **ทีละตัว**: restart เว็บด้วย `TEST_MODE=1 BUG_MODE=Bxx` แล้วรัน **ชุดเต็ม** | ชุด TC ที่ล้ม = คอลัมน์ "TC ที่ต้องล้ม" (ทุกตัวต้องล้ม) + อาจรวม "TC ที่อาจล้มด้วย" · TC อื่นทั้งหมดผ่าน |
| 4 | ดูข้อความที่ล้ม | ข้อความ assert ต้องบอกว่า **ค่าจริงต่างจากค่าที่คาดหวังตรงไหน** (เช่น `expected ฿1,010 received ฿1,000`) ไม่ใช่ล้มเพราะ timeout หรือหา element ไม่เจอ |
| 5 | ลองรวม: `BUG_MODE=B03,B07` และ `BUG_MODE=B01,B05,B09` | ล้มเท่ากับ union ของแต่ละตัว (ไม่หายไป ไม่เพิ่มแปลก ๆ) |
| 6 | ปิดบั๊กทั้งหมดอีกครั้ง | กลับมาผ่าน 51/51 |

คำสั่งตัวอย่าง (ปรับตาม stack ของกลุ่ม):

```text
TEST_MODE=1 <start-web>                       # ไม่มี BUG_MODE
npx playwright test --reporter=list           # คาดหวัง 51 passed

TEST_MODE=1 BUG_MODE=B01 <start-web>
npx playwright test --reporter=list           # คาดหวัง TC-FEE-01 failed อย่างเดียว (ที่เหลือ passed)
```

## 5. Triage: ผลที่ได้ไม่ตรงที่คาด ทำอย่างไร

| อาการ | แปลว่า | ต้องทำ |
|---|---|---|
| TC ที่ระบุล้ม และที่เหลือผ่าน | test จับบั๊กได้ ตรงแผน | บันทึก ✅ |
| TC ที่ระบุ **ผ่าน** ทั้งที่เปิดบั๊ก | **test ผ่านหลอก** หรือเว็บยังไม่ได้ใส่บั๊กจริง | ตรวจว่าเว็บใส่บั๊กตรงจุดตาม "เปิดแล้วผิดอย่างไร" (ยิง API ตรง ๆ ดูค่า) · ถ้าบั๊กถูกใส่แล้วแต่ test ยังผ่าน แก้ assert (มักเกิดจากอ่านผลจากหน้าจอแทนค่าที่คิดจากกฎ หรือยกเลิกการตรวจที่ขอบ) |
| TC **อื่น** (นอกตาราง 2) ล้มด้วย | บั๊กรั่วเกินจุด หรือ test พึ่งกันเอง | ตรวจว่า BUG_MODE กระทบเฉพาะจุด (กติกาข้อ 1–2) · ตรวจว่า TC ไม่ใช้ข้อมูลที่ TC ก่อนหน้าทิ้งไว้ (ต้อง RESET ต้นทุก TC) |
| เปิดบั๊กตัวไหนก็ล้มเยอะทั้งชุด | parse `BUG_MODE` ผิด (เช่นช่องว่าง) หรือ reset ล้าง seed ไม่ครบ | พิมพ์ `BUG_MODE` ออกมาดูตอนเริ่มเว็บ · รันชุดเต็มโดยไม่ตั้ง `BUG_MODE` ให้ผ่านก่อน |
| ล้มด้วย timeout / หา element ไม่เจอ แทนที่จะเป็นค่าต่าง | test เปราะ ไม่ได้จับบั๊กจริง | แก้ให้รอสถานะที่แน่นอน (เช่นรอ `payment-status` = `ชำระแล้ว`) และตรวจค่าตามตาราง |
| เปิดแล้วล้มต่างวันกัน (flaky) | race จริงหรือเวลาจริงรั่ว | ตรวจว่ากฎเวลาอ่านจากนาฬิกาทดสอบ ไม่ใช่เวลาเครื่อง · B08 ต้องล้ม **ทุกครั้ง** เมื่อยิงพร้อมกัน ถ้าบางครั้งผ่านให้เพิ่มจำนวนการยิง (API 10 ครั้งพร้อมกัน) |
| รวมบั๊ก 2 ตัวแล้วผลไม่เท่า union | บั๊กสองตัวแก้ที่เดียวกัน | แยกจุดแก้ของแต่ละตัวให้อิสระต่อกัน |
