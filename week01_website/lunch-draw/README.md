# ข้าวไหนดี · สีลม

สุ่มร้านร้านข้าวกลางวันรอบอาคารจันวาณิชย์ (สีลม) ในระยะเดิน 1 กม. ตามประเภทอาหารที่ทีมโหวต

- **โหวตประเภทอาหาร** สวิตช์ 3 ช่อง ไม่เห็นด้วย / ปกติ / เห็นด้วย ต่อประเภท (ก๋วยเตี๋ยว, ข้าวแกง, ส้มตำ, อาหารญี่ปุ่น ...)
- **โหวตร้าน** สวิตช์แบบเดียวกันที่แต่ละร้านบนกระดาน หรือบนแผนที่ ในห้องแสดงผลรวมของทุกคนข้างสวิตช์
- **บันทึกโหวต** โหวตเป็นแบบร่างก่อน กด "บันทึกโหวต" ในแถบด้านล่างแล้วโอกาสถึงคำนวณใหม่ หน้าจอจึงไม่เด้งระหว่างโหวต
- **ขี้เกียจเดิน** เหลือเฉพาะร้านที่ระยะเดินจริงไม่เกิน 500 ม. (49 ร้าน) และร้านยิ่งใกล้ยิ่งมีโอกาส
- **แผนที่** สลับกระดานเป็นแผนที่เพื่อดูทุกร้าน
  - ชี้หมุดเห็นชื่อร้าน กดหมุดเพื่อดูรายละเอียดและโหวตในแผงด้านขวา
  - ร้านที่อยู่ตึกเดียวกันมีรายการให้เลือก
- **ช่วงราคาต่อคน** เลือกได้หลายช่วง: ฿ ไม่เกิน 60, ฿฿ 60–120, ฿฿฿ 120–250, ฿฿฿฿ 250+ และ "ไม่ระบุ" สำหรับร้านที่ยังไม่มีใครใส่ราคา
- **ห้อง (member)** สร้างห้อง แชร์ลิงก์ ทุกคนโหวตพร้อมกันแบบ **realtime** ใครกดสุ่มร้านก็ได้ ทุกคนเห็นผลเดียวกันทันที
- **กินไปแล้ว 7 วัน** กด "ไปกินร้านนี้" บนผลการสุ่ม ร้านนั้นจะมีโอกาสน้อยลง แล้วค่อยๆ กลับมาปกติใน 7 วัน
- **แก้ข้อมูลร้าน** กดที่แถวในโอกาสของแต่ละร้าน เพื่อตั้ง **ชื่อเล่นร้าน**, **ราคา**, ประเภทอาหาร, ตัวคูณโอกาส หรือ **ปิดร้าน**
  ร้านที่ปิดจะไม่ถูกสุ่ม และไปอยู่ในหมวด "ร้านที่ไม่สุ่ม" ซึ่งเปิดกลับได้
- **เพิ่มร้านเอง** (เมนู "เพิ่มร้าน") ปักหมุดบนแผนที่หรือวางลิงก์ Google Maps ร้านที่เพิ่มเองลบได้
- **จัดการประเภทอาหาร** (`/categories`) เพิ่ม แก้ชื่อ หรือลบประเภทอาหาร
- **ประวัติ** ทุกผลการสุ่มมีป้าย ไปกิน / ไม่ได้ไปกิน / รอยืนยัน

## ที่เก็บข้อมูล: ไฟล์ JSON หรือ Redis

ระบบเลือกโหมดให้เองตาม environment

| | บนเครื่อง (`npm run dev`, `next start`, e2e) | Vercel (มี `KV_REST_API_URL` + `KV_REST_API_TOKEN`) |
| --- | --- | --- |
| ร้าน ประเภทอาหาร คะแนน | `data/restaurants.json`, `categories.json`, `ratings.json` (อยู่ใน git) | Redis · ครั้งแรกคัดลอกจากไฟล์ใน `data/` ที่ deploy ไป หลังจากนั้นค่าที่ทีมแก้อยู่ใน Redis |
| ห้อง โหวต ประวัติ | `data/state.json` (gitignore) | Redis · ห้องหมดอายุเองใน 3 วัน · ประวัติเก็บ 1,000 ครั้งล่าสุด |
| realtime | Server-Sent Events (`/api/events`) | หน้าเว็บถามทุก 1 วินาที (`/api/poll`) |

- บังคับใช้โหมดไฟล์ได้ด้วย `LUNCH_STORAGE=file`
- โหวตในห้องเก็บเป็น field ต่อคนต่อรายการใน Redis hash คนสองคนโหวตพร้อมกันจึงไม่ทับกัน
- ลองโหมด Redis บนเครื่อง: `node e2e/mock-upstash.mjs 8079` แล้วรัน `KV_REST_API_URL=http://localhost:8079 KV_REST_API_TOKEN=dev npx next start -p 3400`

### Deploy บน Vercel

1. Root Directory = `week01_website/lunch-draw`
2. Storage → Upstash for Redis → เชื่อมกับโปรเจกต์ (Custom Prefix `KV`) จะได้ `KV_REST_API_URL` และ `KV_REST_API_TOKEN`
3. Redeploy · ไม่ต้องตั้งค่าอื่น · **ห้ามตั้ง `LUNCH_TEST`** (เปิด API ล้างข้อมูลสำหรับ test)

ค่าที่ทีมแก้บน Vercel อยู่ใน Redis ไม่ได้กลับเข้า git ถ้าแก้ `data/restaurants.json` ใน repo แล้วอยากให้ production ใช้ไฟล์ใหม่ ต้องลบ key `ld:restaurants` ใน Redis ก่อน (ค่าที่แก้ใน production จะหายไปด้วย)

## สูตรน้ำหนัก

```
น้ำหนักร้าน = ตัวคูณโอกาส (0.5–5)
            × ตัวคูณประเภทอาหารที่ดีที่สุดของร้าน   max(0.1, 1 + 0.5 × ผลโหวตสุทธิของแนวนั้น)
            × ตัวคูณโหวตร้าน                     max(0.1, 1 + 0.5 × ผลโหวตสุทธิของร้านนั้น)
            × ตัวคูณกินไปแล้ว                    0.2 วันที่กิน → 1.0 เมื่อครบ 7 วัน (เพิ่มแบบเส้นตรง)
            × ตัวคูณระยะ (เฉพาะขี้เกียจเดิน)       2.0 ที่ออฟฟิศ → 1.0 ที่ 500 ม.
โอกาส       = น้ำหนักร้าน / ผลรวมน้ำหนักของร้านที่ผ่านตัวกรอง (ไม่ปิด, ระยะ, ราคา)
```

โค้ดอยู่ที่ `src/lib/odds.ts` และเทสต์อยู่ที่ `src/lib/odds.test.ts`

## เริ่มใช้งาน

```bash
npm install     # คัดลอก worker ของ MapLibre ไปไว้ใน public/ ให้อัตโนมัติ
npm run dev     # http://localhost:3000
```

| คำสั่ง | ทำอะไร |
| --- | --- |
| `npm run data:fetch` | ดึงร้านใหม่จาก OpenStreetMap และคำนวณระยะเดินจริง โดยค่าที่ทีมแก้และเบอร์ร้านจะไม่หาย |
| `npm test` | unit test ของสูตรน้ำหนัก |

พิกัดจุดศูนย์กลางอยู่ที่ `src/lib/geo.ts` (`OFFICE`) **เป็นพิกัดประมาณ** ถ้าแก้แล้วให้รัน `npm run data:fetch` ใหม่

## E2E test (Playwright)

```bash
npm run e2e:all      # รันทั้งหมด: 72 test case แล้วสร้าง GIF และไฟล์ Excel
npm run e2e          # รัน test อย่างเดียว (build + start เซิร์ฟเวอร์ทดสอบที่ :3200)
npm run e2e:gifs     # แปลงวิดีโอของแต่ละ test เป็น GIF
npm run e2e:report   # สร้างไฟล์ Excel จากผลรันล่าสุด (ต้องมี python และ openpyxl)
```

- **ข้อมูลแยก:** เซิร์ฟเวอร์ทดสอบเริ่มจากข้อมูลตายตัวใน `e2e/data` (คัดลอกไป `e2e/.data`) ไม่แตะ `data/` ผลทดสอบจึงไม่เปลี่ยนตามที่ทีมแก้ในแอป และรีเซ็ตข้อมูลก่อนทุก test ผ่าน `POST /api/test/reset` ซึ่งเปิดใช้เฉพาะเมื่อ `LUNCH_TEST=1`
- **ไม่ใช้ internet:** บล็อกแผนที่และเส้นทางเดินจากภายนอกระหว่างทดสอบ ผลจึงไม่ขึ้นกับเน็ต
- **ผลลัพธ์:**
  - `e2e/report/E2E-TEST-REPORT.xlsx` มี 3 ชีต: **สรุปผล** (ตามระดับ ตามโมดูล และเกณฑ์ปล่อยใช้งาน), **Test Cases** (สิ่งที่ทดสอบ ขั้นตอน ผลที่คาดหวัง ผลจริง สถานะ เวลา และลิงก์ภาพ) และ **Defects**
  - `e2e/report/gifs/` GIF ของทุก test ที่เปิดหน้าเว็บ (เปิด `index.html` เพื่อดูรวม)
  - `e2e/report/screenshots/` ภาพหน้าจอตอนจบของแต่ละ test
  - `e2e/report/html/` รายงาน HTML ของ Playwright (`npx playwright show-report e2e/report/html`)
- **เพิ่ม test ใหม่:** เขียน test ใน `e2e/tests/*.spec.ts` โดยตั้งชื่อเป็น `TC-XXX-NN ชื่อ @P1|P2|P3` แล้วเพิ่มรายละเอียดใน `e2e/test-cases.json` ถ้าสองที่นี้ไม่ตรงกัน สคริปต์สร้าง Excel จะแจ้ง error
- **บันทึกบั๊ก:** บั๊กที่พบและแก้แล้วบันทึกไว้ใน `e2e/defects.json` ส่วน test ที่ล้มและยังไม่ได้บันทึกจะถูกเพิ่มลงชีต Defects ให้อัตโนมัติ

## Stack

Next.js 16 (App Router, Route Handlers เป็นหลังบ้าน) · เก็บข้อมูลเป็น JSON file (บนเครื่อง) หรือ Upstash Redis (Vercel) · SSE หรือ polling สำหรับ realtime · Tailwind v4 · MapLibre + CARTO dark tiles · lucide icons
ข้อมูลร้านจาก OpenStreetMap และระยะเดินจาก routing.openstreetmap.de ทั้งหมดฟรี ไม่ต้องใช้ API key
