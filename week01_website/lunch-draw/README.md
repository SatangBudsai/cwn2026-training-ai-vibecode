# ข้าวไหนดี · สีลม

จับสลากร้านข้าวกลางวันรอบอาคารจันวาณิชย์ (สีลม) ในระยะเดิน 1 กม. ตามแนวอาหารที่ทีมโหวต

- **โหวตแนวอาหาร** กด + แนวที่อยากกิน กด − แนวที่ไม่เอา (ก๋วยเตี๋ยว, ข้าวแกง, ส้มตำ, ญี่ปุ่น ...)
- **ขี้เกียจเดิน** เหลือเฉพาะร้านที่ระยะเดินจริงไม่เกิน 500 ม. (49 ร้าน)
- **ช่วงราคาต่อคน** เลือกได้หลายช่วง: ฿ ไม่เกิน 60, ฿฿ 60–120, ฿฿฿ 120–250, ฿฿฿฿ 250+ และ "ไม่ระบุ" สำหรับร้านที่ยังไม่มีใครใส่ราคา
- **ห้อง (member)** เปิดห้อง แชร์ลิงก์ ทุกคนโหวตพร้อมกันแบบ **realtime** ใครกดจับสลากก็ได้ ทุกคนเห็นผลเดียวกันทันที
- **กินไปแล้ว 7 วัน** กด "ไปกินร้านนี้" บนผลจับสลาก ร้านนั้นจะมีโอกาสน้อยลง แล้วค่อยๆ กลับมาปกติใน 7 วัน
- **แก้ข้อมูลร้าน** กดที่แถวในกระดานโอกาส เพื่อตั้ง **ชื่อเล่นร้าน**, **ราคา**, แนวอาหาร, น้ำหนักพื้นฐาน หรือ **ปิดร้าน**
  ร้านที่ปิดจะไม่ถูกสุ่ม และไปอยู่ในหมวด "ร้านที่ปิดไว้" ซึ่งเปิดกลับได้

## เก็บข้อมูลเป็นไฟล์ ไม่ใช้ database

| ไฟล์ | เก็บอะไร | อยู่ใน git |
| --- | --- | --- |
| `data/restaurants.json` | ร้านทั้งหมด และค่าที่ทีมแก้ (ชื่อเล่น ราคา แนวอาหาร น้ำหนัก ปิดร้าน) | ใช่ commit ได้เลย |
| `data/state.json` | ห้อง โหวต และประวัติผลจับสลาก (ใช้คิดโทษ 7 วัน) | ไม่ (gitignore) |

- เซิร์ฟเวอร์อ่านไฟล์ไว้ในหน่วยความจำ แล้วเขียนกลับทุกครั้งที่มีการเปลี่ยนแปลง (เขียนไฟล์ชั่วคราวก่อนแล้วค่อย rename)
- ถ้าแก้ `restaurants.json` เอง หรือ `git pull` มา เซิร์ฟเวอร์จะโหลดไฟล์ใหม่ให้อัตโนมัติ
- ห้องที่ไม่มีใครใช้ 3 วันจะถูกลบ และประวัติผลจับสลากเก็บไว้ 1,000 ครั้งล่าสุด

## Realtime

ใช้ Server-Sent Events ที่ `GET /api/events?room=CODE` แทนการ polling

- เซิร์ฟเวอร์ส่ง event `room` ทุกครั้งที่มีคนโหวต เปลี่ยนตัวกรอง หรือจับสลาก
- เซิร์ฟเวอร์ส่ง event `restaurants` ทุกครั้งที่มีคนแก้ร้านหรือกด "ไปกินร้านนี้"
- หน้าสุ่มคนเดียวก็รับ `restaurants` ด้วย จึงเห็นการแก้ของคนอื่นทันที

ข้อจำกัดคือต้องรันเป็น Node process เดียวที่รันค้างไว้ (`npm run dev` หรือ `npm run build && npm start`) บนเครื่องหรือ VPS
**ใช้กับ Vercel ไม่ได้** เพราะ Vercel ไม่มี disk ถาวร และแต่ละ request อาจรันคนละเครื่อง

## สูตรน้ำหนัก

```
น้ำหนักร้าน = น้ำหนักพื้นฐาน (0.5–5)
            × ตัวคูณแนวอาหารที่ดีที่สุดของร้าน   max(0.1, 1 + 0.5 × ผลโหวตสุทธิของแนวนั้น)
            × ตัวคูณกินไปแล้ว                    0.2 วันที่กิน → 1.0 เมื่อครบ 7 วัน (เพิ่มแบบเส้นตรง)
โอกาส       = น้ำหนักร้าน / ผลรวมน้ำหนักของร้านที่ผ่านตัวกรอง (ไม่ปิด, ระยะ, ราคา)
```

โค้ดอยู่ที่ `src/lib/odds.ts` และเทสต์อยู่ที่ `src/lib/odds.test.ts`

## เริ่มใช้งาน

```bash
npm install     # คัดลอก worker ของ MapLibre ไปไว้ใน public/ ให้อัตโนมัติ
npm run dev     # http://localhost:3000
```

| คำสั่ง | ทำอะไร |
| --- | --- |
| `npm run data:fetch` | ดึงร้านใหม่จาก OpenStreetMap และคำนวณระยะเดินจริง โดยค่าที่ทีมแก้และเบอร์ร้านจะไม่หาย |
| `npm test` | unit test ของสูตรน้ำหนัก |

พิกัดจุดศูนย์กลางอยู่ที่ `src/lib/geo.ts` (`OFFICE`) **เป็นพิกัดประมาณ** ถ้าแก้แล้วให้รัน `npm run data:fetch` ใหม่

## E2E test (Playwright)

```bash
npm run e2e          # build + start เซิร์ฟเวอร์ทดสอบที่ :3200 แล้วรัน 44 test case
npm run e2e:report   # สร้างไฟล์ Excel จากผลรันล่าสุด (ต้องมี python และ openpyxl)
```

- **ข้อมูลแยก:** เซิร์ฟเวอร์ทดสอบใช้ข้อมูลที่ `e2e/.data` ไม่แตะ `data/restaurants.json` และรีเซ็ตข้อมูลก่อนทุก test ผ่าน `POST /api/test/reset` ซึ่งเปิดใช้เฉพาะเมื่อ `LUNCH_TEST=1`
- **ไม่ใช้ internet:** บล็อกแผนที่และเส้นทางเดินจากภายนอกระหว่างทดสอบ ผลจึงไม่ขึ้นกับเน็ต
- **ผลลัพธ์:**
  - `e2e/report/E2E-TEST-REPORT.xlsx` มี 3 ชีต: **สรุปผล** (ตามระดับ ตามโมดูล และเกณฑ์ปล่อยใช้งาน), **Test Cases** (สิ่งที่ทดสอบ ขั้นตอน ผลที่คาดหวัง ผลจริง สถานะ เวลา และลิงก์ภาพ) และ **Defects**
  - `e2e/report/screenshots/` ภาพหน้าจอตอนจบของแต่ละ test
  - `e2e/report/html/` รายงาน HTML ของ Playwright (`npx playwright show-report e2e/report/html`)
- **เพิ่ม test ใหม่:** เขียน test ใน `e2e/tests/*.spec.ts` โดยตั้งชื่อเป็น `TC-XXX-NN ชื่อ @P1|P2|P3` แล้วเพิ่มรายละเอียดใน `e2e/test-cases.json` ถ้าสองที่นี้ไม่ตรงกัน สคริปต์สร้าง Excel จะแจ้ง error
- **บันทึกบั๊ก:** บั๊กที่พบและแก้แล้วบันทึกไว้ใน `e2e/defects.json` ส่วน test ที่ล้มและยังไม่ได้บันทึกจะถูกเพิ่มลงชีต Defects ให้อัตโนมัติ
